# M9 反馈闭环与冲突消解

> 设计输入：ARCHITECTURE 7.2。验证点（ROADMAP）：对某条意见 👎 后再提同类代码，该意见不再出现。
> 用户在判定门对 5 个未决点逐条拍板（2026-10-23），见 D1~D5；其余细节按下表取默认值。

## 拆分

范围跨 integration / memory / review 三个服务，一个会话做不完，按 ROADMAP「里程碑过大时」拆：

| 子项 | 内容 | 独立验证点 |
|---|---|---|
| **M9a** 反馈进来 | 行级评论带指纹标记、integration 轮询 👎 / 回复 → `FindingFeedbackReceived` → memory LLM 抽取 + ADD/UPDATE/DELETE 消解 | 对真实 PR 上一条 CodeMind 行级评论 👎 后，memory 里出现对应的 `REJECTED_PATTERN` 记忆；重复轮询不重复学习 |
| **M9b** 过滤生效 | review 的 Dedup & Filter（召回否决记忆 + LLM 判定同类）+ 真实端到端验收 | ROADMAP M9 原验证点 |

## M9b 实施计划（S2）

> **执行方式：** 本计划按 `superpowers:executing-plans`（链式依赖、单会话内顺序执行）实施，
> 每个任务配 `superpowers:test-driven-development`；测试失败走 `superpowers:systematic-debugging`。

**目标**：review 侧接入 memory 否决记忆召回，评审产出的 Finding 在落报告前先过滤掉被否决的同类意见
（D3 方案 A：召回候选 + LLM 判定），判不出来时放行不压制真缺陷。

**架构**：新增 domain 端口 `MemoryRecallPort`（只读召回，不依赖 Spring）+ `infrastructure/memory` 下的
Feign 适配器（镜像 `infrastructure/scm` 的既有写法）；domain 新增 `FindingFilter`，对每条 Finding 单独
召回 + 单独问 LLM（简单可靠，先不做批量合并请求——Finding 数量通常个位数，N 次调用可接受）；
`ReviewExecutionService` 在 `reportBuilder.build` 前用 `FindingFilter` 处理 `result.allFindings()`。

**Tech Stack**：Spring Cloud OpenFeign（已在模块依赖里，M7a 引入）；复用 M4 起的 `LlmClient` / `JsonFences`。

**Spec**：`docs/ARCHITECTURE.md` 7.2 第 5 步、7.3；`docs/plans/M9.md` D3、D11（本文件前文）；
`docs/ROADMAP.md` M9 验证点。

### Global Constraints

- minScore 召回阈值沿用 M9a 冲突消解的 `0.05`（`FeedbackLearningService.CONFLICT_MIN_SCORE`）
- 召回 kind 固定 `REJECTED_PATTERN`；`project` 参数 = `task.repo()`（与 M9a `event.repo()` 用法一致，即仓库全名字符串）
- memory 不可用（Feign 调用抛异常）时**放行该 Finding**（不压制），并在 `degradations` 记一条日志级降级信息，
  不中断整体评审流程（与 M4 `ReviewAgent` 降级思路一致：局部失败不致整体失败）
- `MemoryRecallPort` 是纯接口放在 `domain/memory` 包，不依赖 Spring/Feign 类型（与 `ScmContentPort` 同样的分层约束）
- `FindingFilter` 是 domain 纯类（无 Spring 注解），LLM 判定走已有 `com.codemind.review.domain.agent.LlmClient` 端口
- 不改 `ReviewReportBuilder`（它是纯函数，不碰基础设施）；过滤发生在调用它之前

### Review Focus

- 召回失败（Feign 抛异常／memory 服务不可达）时 Finding 必须放行，不能因为过滤器出错而丢真缺陷
- LLM 判定输出非法/畸形时同样放行（降级），不能因为解析失败就把 Finding 判定为"应过滤"
- 没有召回到任何候选记忆（空列表）时必须直接放行，不该为空结果调用 LLM
- 同一个 Finding 被多条候选记忆覆盖时，只要 LLM 判定命中其一即过滤，不要求全部命中
- CORRECTNESS 类的真缺陷（NPE 等）即使 category 恰好和某条否决记忆接近，LLM 判定需看語义而非仅看 category 字符串，
  避免把"同 category 但不同语义"的意见也滤掉——这条在 Task 3 的 prompt 设计里用正反例约束，并在 T6 真实验收时复核

package com.codemind.review.domain.finding;

import com.codemind.review.domain.agent.JsonFences;
import com.codemind.review.domain.agent.LlmClient;
import com.codemind.review.domain.memory.MemoryRecallException;
import com.codemind.review.domain.memory.MemoryRecallPort;
import com.codemind.review.domain.memory.RecalledMemory;
// ...

public final class FindingFilter {

    private static final int TOP_K = 5;
    private static final double MIN_SCORE = 0.05; // Global Constraints：沿用 M9a CONFLICT_MIN_SCORE

    private final MemoryRecallPort recallPort;
    private final LlmClient llmClient;
    private final int maxRetries;

    public FindingFilter(MemoryRecallPort recallPort, LlmClient llmClient, int maxRetries) { ... }

    public FilterOutcome filter(String project, List<Finding> findings) {
        List<Finding> kept = new ArrayList<>();
        List<String> degradations = new ArrayList<>();
        for (Finding finding : findings) {
            if (shouldKeep(project, finding, degradations)) {
                kept.add(finding);
            }
        }
        return new FilterOutcome(kept, degradations);
    }

    private boolean shouldKeep(String project, Finding finding, List<String> degradations) {
        List<RecalledMemory> candidates;
        try {
            candidates = recallPort.recallRejectedPatterns(project,
                    finding.category() + ": " + finding.message(), TOP_K, MIN_SCORE);
        } catch (MemoryRecallException e) {
            degradations.add("记忆召回失败，放行 fingerprint=" + finding.fingerprint() + "：" + e.getMessage());
            return true;
        }
        if (candidates.isEmpty()) {
            return true;
        }
        Boolean filtered = judge(finding, candidates, degradations);
        return filtered == null || !filtered;
    }

    private Boolean judge(Finding finding, List<RecalledMemory> candidates, List<String> degradations) {
        String user = userPrompt(finding, candidates);
        for (int attempt = 0; attempt <= maxRetries; attempt++) {
            try {
                String raw = llmClient.complete(SYSTEM_PROMPT, user);
                return parse(raw);
            } catch (LlmClient.LlmException | IllegalArgumentException e) {
                // 重试
            }
        }
        degradations.add("LLM 判定失败，放行 fingerprint=" + finding.fingerprint());
        return null; // null = 放行
    }

    private static Boolean parse(String raw) {
        // 用 JsonFences.strip + Jackson 严格解析 {"filtered": true|false}
        // 缺字段或类型不对 -> throw IllegalArgumentException
    }

    private static String userPrompt(Finding finding, List<RecalledMemory> candidates) { ... }

    private static final String SYSTEM_PROMPT = """
            你是代码评审系统的记忆过滤器。开发者此前否决过一些评审意见，形成了「否决规则」。
            现在有一条新的评审意见，以及若干条可能相关的否决规则。
            判断这条新意见是否属于某条否决规则描述的同类问题——即如果再给开发者看，
            会不会被同样否决。只有在新意见确实是否决规则覆盖的同一类问题时才判定为 filtered=true。
            不同维度、不同语义的问题即使表面措辞相似也不算同类，必须判 filtered=false。
            否决规则不会无中生有地扩大到它没提到的问题上。
            只输出 JSON：{"filtered": true|false}，不要任何解释。""";
}
