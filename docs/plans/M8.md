# M8 memory-service：L1/L2 记忆、混合检索

> 设计输入：ARCHITECTURE 7。验证点（ROADMAP）：单测证明写入与召回排序符合打分公式。
> S1/S3 的未决点由用户授权「以推荐为准」（2026-10-23），下表即设计共识。

## 设计共识（S1）

| # | 问题 | 决定 | 理由 |
|---|---|---|---|
| D1 | 范围 | 只做 memory-service 自身：L2 写入 / 混合召回 / 打分 / 归档 / 人工删除，L1 指纹集合。不接 review 的 RecallContext 与 Feign，不做反馈抽取与冲突消解（M9），不做 L3 | ROADMAP M8 只列 memory；接线随 M9 Dedup & Filter 一起做才有验证点 |
| D2 | L1 做多少 | 只做「已发布 Finding 指纹」集合，PG 表 `memory.task_fingerprint`，按 `(repo, pr_number)` 归属。ChangeMap / ChunkSummary 的跨 push 复用留 M10 | 指纹是 M10 增量去重的直接输入，需要比 Redis 更持久；ChangeMap 复用没有 M10 的调用方就无从验证 |
| D3 | Embedding | domain 端口 `Embedder`；默认实现 `HashingEmbedder`（字符 bigram + ASCII 词特征哈希，256 维，L2 归一化，确定性） | 中转端点 `/v1/models` 只有 Claude 系列（2026-10-23 实测），无 embedding 模型。哈希向量可确定性测试；换真实模型只换适配器 + 改维度迁移 |
| D4 | 全文检索 | `pg_trgm` 的 `similarity() > 0`，不用 `tsvector`；**不建 GIN**（实现中修订） | PG 默认分词切不开中文；`en_US.utf8` 下 pg_trgm 能切中文三元组（实测）。`%` 运算符默认阈值 0.3 会滤掉中文近义句（实测约 0.19），GIN 只服务 `%` |
| D5 | similarity | `max(clamp(vectorSim), clamp(textSim))`，clamp 到 [0,1]，NaN 按 0 | 两路任一强命中都该召回；加权会稀释单路强命中。逐路 clamp 防 NaN 经 `Math.max` 传染（S6） |
| D6 | decay | `decay(Δt) = 0.5^(Δt / halfLife)`，默认半衰期 30 天，Δt 从 `reinforced_at`（写入或被再次写入时刷新）算起，Δt<0 按 0 | 召回不刷新时间：读不改状态，排序可复现。M9 的反馈强化走写入路径 |
| D7 | importance | 写入方给出，(0,1]，缺省 0.5；同内容再次写入取 `max(旧, 新)` 并刷新 `reinforced_at` | M9 抽取否决记忆时由 LLM / 规则给出，M8 不臆造来源 |
| D8 | 召回流程 | SQL 只取候选（向量 top-N ∪ 三元组 top-N，`N = max(topK, 50)`，过滤 project / ACTIVE / 可选 kind，两路都是**精确扫描、不建 HNSW**），打分、阈值过滤（`minScore`，默认 0）、排序、取 top-k 全在 domain 纯函数 `MemoryRanker` | 验证点要求「排序符合公式」，公式与排序放纯函数才能单测直证。HNSW 是全表近似索引，带 project 过滤时先取全局 `ef_search`(40) 个近邻再过滤，小项目会拿不满 N（S6 双轴共同指出） |
| D9 | 并列 | score 降序 → importance 降序 → id 升序 | 结果确定 |
| D10 | 遗忘 | `retention = importance × decay(Δt)` 低于阈值（默认 0.05）→ `ARCHIVED`；内部端点手动触发，不加定时任务。库侧按 `reinforced_at < now - halfLife·log2(1/阈值)` 预筛（importance ≤ 1 时的必要条件），逐条精确判定后按 `reinforced_at` 条件更新。人工删除为物理删除 | 「长期低于阈值」与 similarity 无关；预筛免得整项目载入内存（S6）；定时任务留 M12/M13 |
| D11 | 写入去重 | 唯一键 `(project, kind, content_hash)`，`content_hash = sha256(normalize(content))`（去首尾空白、压缩空白） | 同一记忆反复写入只强化不重复 |
| D12 | kind | `CONVENTION`（团队规范）/ `REJECTED_PATTERN`（被否决的意见模式）/ `COMMON_DEFECT`（常见缺陷） | ARCHITECTURE 7.1 L2 三类内容 |
| D13 | 存储 | 独立 schema `memory`，Flyway `db/memory-migration`，同 integration 做法 | 与 review / integration 的迁移历史互不扫描 |

## 接口（内部，无鉴权，与 M7a 的 internal 端点同一缺口）

- `POST /internal/memories` `{project, kind, content, importance?}` → 记忆（含是否新建）
- `POST /internal/memories/recall` `{project, query, topK?, kind?, minScore?}` → 按 score 降序，每条带 `similarity / importance / decay / score`
- `DELETE /internal/memories/{id}` → 404 / 204
- `POST /internal/memories/archive?project=` → 归档条数
- `POST /internal/task-fingerprints` `{repo, prNumber, fingerprints[]}` → 新增条数；`GET /internal/task-fingerprints?repo=&prNumber=` → 集合（按指纹字典序）

输入上限：content ≤ 2000 字符（归一化后）、query ≤ 8000、project ≤ 255、topK ∈ [1, 50]、minScore ∈ [0, 1]、
指纹 ≤ 128 字符且单批 ≤ 1000、半衰期 ≥ 1ms。参数非法统一 400 + `Result`；库里脏数据走 500。

## S6 评审与处理（固定点 `e94223e`，标准轴 / 规格轴两个独立子代理）

标准轴 0 硬违规；规格轴 2 严重。回 S5 已修：

- 严重：HNSW 带 project 过滤会拿不满候选 → 去掉 HNSW，精确扫描（D8）；`Math.max(NaN, x)` 吞掉另一路 → 逐路 clamp（D5），补用例
- 半衰期 < 1ms 除以 0 → 构造时拒绝；仓储脏数据 IAE → 转 `IllegalStateException`（500）；
  归档整项目载入 → 库侧 cutoff 预筛；缺参 / 类型错不走 `Result` → 补 handler；content / query / project 无上限 → 加上限；
  `domain.memory` ↔ `domain.recall` 循环 → `MemoryCandidate` 挪进 `memory`；`Embedder.dimensions()` 无人用 → 删；
  `@ConditionalOnMissingBean` 用在普通配置类 → 删；ranker 不防 ARCHIVED → 过滤；`TaskFingerprintService` 无单测 → 补
- 计划偏离（GIN、零向量、topK 上限）→ 本文件已同步
